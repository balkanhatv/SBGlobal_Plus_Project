## 1. Management System Specification Standard (applies to every MS in every suite)

Every Foundational/Critical Management System is a business domain that **consumes Core capabilities** and never re-implements them. The table below states shared platform contracts; it does not substitute for MS-specific business semantics.

| Dimension | Shared platform contract / evidence rule |
|---|---|
| Purpose/Scope/Actors/Roles | Must be owned by the specific MS/suite; a catalog name alone is insufficient |
| Workflows/States/Rules/Approvals | Must include MS-specific behavior where applicable; approvals execute through Core Workflow Engine |
| Documents/Templates | MS must identify its applicable business documents/templates; rendering/storage uses Core Document Management |
| Notifications | MS must identify meaningful business events/recipients; delivery uses Core notification engine and channel policy |
| Reports/Dashboards/KPIs/Analytics | MS/suite must identify business-specific KPI/report needs; Core Reporting & BI provides shared engine |
| APIs/Events | First-party typed application contracts use **tRPC where appropriate**; REST/OpenAPI is exposed for external interoperability; MS-specific resources/events must be named at appropriate Foundation/Architecture depth rather than assumed by this row |
| Integrations | MS-specific integration needs must be identified; technical connectors/profiles use Core Integration Management |
| Security/Compliance/Audit | Shared entitlement + RBAC/ABAC + tenant/industry-context isolation + audit fabric apply; industry/MS-specific compliance/authorization constraints must be named where applicable |
| AI/Automation | Shared Core AI platform applies; MS-specific AI purpose/context/guardrails must be identified where applicable |
| Web/Mobile/Desktop | Shared experience framework applies; MS features remain role/tenant/industry scoped and surface applicability must be identified |
| Configuration/Entitlements | MS/module enablement follows the entitlement chain; MS-specific configurable business policies must be identified where applicable |
| Testing/Acceptance | Shared tenant-isolation and security test families apply; MS-specific workflow/rule acceptance scenarios must exist where required |
| Dependencies | Each MS must name its actual Core + intra-suite/cross-domain dependencies; generic inheritance is insufficient |

## 2. Per-suite completion (coverage map requiring substantive owner verification)

### 2.1 Healthcare & Diagnostics (HLT) `[SD — consolidation only]`
**Branches/Departments/Locations:** F-07 §1.4 (branches incl. franchise; 9+ lab departments; collection centers as location type). **MS modules:** LIS fully enumerated (F-07 §1.4); HMS/RIS/PMS/CMS operational detail is owned by F-13 §1 and must be verified there rather than inferred here. **Documents/Templates:** invoice + report defaults `[SD: S2.7]`, consent forms, requisitions, QR-verified certificates. **Notifications:** appointment reminders, report-ready, critical-value alerts (BR-HLT-01), payment receipts. **KPIs:** revenue, patients, doctors, reports, pending samples, collections, TAT compliance, rejection rate `[SD: S2.7 dashboard]`. **Events:** patient.registered, sample.collected/received/rejected, result.entered/verified/approved, report.published, invoice.paid. **Integrations:** HL7/FHIR/HIS/EMR/EHR/analyzers `[SD]`. **Compliance:** HIPAA-readiness, DPDP, consent records. **Entitlements:** per-MS licensing (e.g., LIS-only tenant). **Dependencies:** LIS↔Billing (order→invoice), LIS↔Inventory (reagent consumption), all→Communication.

### 2.2 Education (EDU) `[AC]`
**Branches/Departments/Locations:** campuses (branch), academic departments/faculties, classrooms/labs/hostels/transport routes as locations. **MS modules:** SMS/CUM — admissions, student records, attendance, timetable, promotion; CTM — batches, enquiry funnel, fee plans; LMS — courses, content, assignments, quizzes, certificates; EMS — exam setup, halls, evaluation, results, re-evaluation. **Documents:** admission forms, ID cards, hall tickets, mark sheets, transfer/leaving certificates, fee receipts (QR-verifiable). **Notifications:** admission status, fee due/receipt, attendance shortfall, exam schedule, result publication (parent + student channels). **KPIs:** enrollment, attendance %, fee collection/outstanding, pass %, teacher utilization, admission conversion. **Events:** application.submitted/approved, student.enrolled, attendance.marked, exam.published, result.approved, fee.paid. **Integrations:** payment gateways, SMS/WhatsApp, video-class providers (via Integration profiles). **Compliance:** minor-data protection (guardian consent), DPDP. **Entitlements:** per-MS (e.g., coaching center = CTM+LMS only). **Dependencies:** EMS↔SMS (student registry), LMS↔SMS, Fees↔Core Billing.

### 2.3 eCommerce/Retail (RTL) `[AC]`
**Branches/Locations:** stores (branch), warehouses, fulfillment centers, marketplace as virtual channel. **MS modules:** RSM — store ops, staff shifts, cash management; POS — registers, sessions, offline sales; IWM — bins, putaway, picking, cycle counts, transfers; OMS — carts, orders, payments, shipments, returns; MKT — sellers, listings, commissions, settlements. **Documents:** invoices (GST), delivery challans, credit notes, shipping labels (barcode), settlement statements. **Notifications:** order status ladder, payment confirmation, delivery updates, low-stock alerts, settlement notices. **KPIs:** sales, AOV, conversion, stock turnover, fill rate, return rate, seller performance. **Events:** order.placed/paid/shipped/delivered/returned, stock.low, pos.session.closed, seller.settled. **Integrations:** payment gateways, couriers/logistics, marketplace channels. **Compliance:** GST/tax rules, consumer-protection return policies. **Entitlements:** channel-level (POS-only vs full omnichannel). **Dependencies:** OMS↔IWM (reservation, BR-RTL-01), MKT↔Core commission engine, POS↔Synchronization Policy.

### 2.4 Hospitality (HSP) `[AC]`
**Branches/Locations:** properties (branch), outlets (restaurant/bar), halls/venues, floors/rooms. **MS modules:** HMS — front office, folios, housekeeping, night audit; RMS — tables, KOT, kitchen display, menu engineering; BEM — enquiries, function sheets, event billing; RBM — availability, rate plans, channel inventory. **Documents:** registration cards, folios/invoices, function sheets, KOT tickets, event contracts. **Notifications:** booking confirmation, pre-arrival, check-out folio, event reminders, no-show alerts. **KPIs:** occupancy %, ADR, RevPAR, covers, table turnover, event conversion, guest satisfaction. **Events:** reservation.confirmed/cancelled/noshow, guest.checkedin/out, kot.fired/served/void, event.booked. **Integrations:** OTA/channel managers, payment gateways, door-lock/PBX (profiles). **Compliance:** guest-ID/KYC rules, local lodging regulations, F&B safety postures (jurisdiction-configurable). **Entitlements:** per-MS (restaurant-only tenant = RMS). **Dependencies:** RBM↔HMS (availability→folio), RMS/BEM↔Core Billing, housekeeping↔ticketing via Core workflow (not the SFM suite).

### 2.5 Manufacturing (MFG) `[AC]`
**Branches/Locations:** plants (branch), production lines/work centers, warehouses/bins, maintenance shops. **MS modules:** PMS — planning, orders, routing, WIP, output; IWM — industrial materials/warehouse domain (dedicated operational depth in F-13 §2.3; never inferred from Retail); QMS — plans, inspections, NCR, CAPA, certificates; PRO — PR/RFQ/PO/GRN/3-way match; MMS — assets, preventive schedules, work orders, downtime. **Documents:** work orders, job cards, QC certificates, GRNs, POs, test reports, batch genealogy records. **Notifications:** order release, QC hold, reorder alerts, maintenance due, breakdown escalation. **KPIs:** OEE, yield, scrap %, on-time production, inventory turns, PO cycle time, MTBF/MTTR. **Events:** production.released/completed, lot.qchold/disposed, pr.created, grn.received, asset.breakdown. **Integrations:** weighbridge/PLC/SCADA-ready via profiles, vendor portals. **Compliance:** ISO-9001-style QMS posture, safety/audit trails, batch traceability (BR-MFG-04). **Entitlements:** per-MS. **Dependencies:** PMS↔IWM (issue/receipt), QMS gates PMS+PRO, MMS↔PMS (downtime).

### 2.6 Professional Services (PSV) `[AC]`
**Branches/Locations:** offices (branch), practice groups (department), client sites, studios. **MS modules:** CRM — leads, pipeline, proposals, contracts; PJM — WBS, milestones, tasks, change requests; SDM — SLAs, tickets, deliverables, acceptance; RTM — capacity, allocation, timesheets, expenses; SGM — bookings, shoots, editing pipeline, delivery vault. **Documents:** proposals, MSAs/SOWs, invoices, timesheet reports, acceptance certificates, delivery notes. **Notifications:** pipeline stage changes, timesheet reminders/approvals, milestone due, budget alerts (BR-PSV-02), delivery-ready. **KPIs:** pipeline value, win rate, utilization %, realization, project margin, on-time delivery, revision count (SGM). **Events:** lead.qualified, deal.won, project.milestone.accepted, timesheet.approved, booking.delivered. **Integrations:** email/calendar, accounting export, e-sign (Core trust services). **Compliance:** client-confidentiality (ABAC data-sensitivity attribute), contract retention. **Entitlements:** per-MS (studio-only tenant = SGM+CRM). **Dependencies:** PJM↔RTM (allocation→timesheet→billing, BR-PSV-01), CRM→PJM (won→project), all→Core Billing.

### 2.7 Government & Public Sector (GOV) `[AC]`
**Branches/Locations:** head office/directorate (branch), zonal/ward offices, service counters, field jurisdictions. **MS modules:** CSM — service catalog, requests, SLA engine binding, grievances, appeals; CFM — file numbering, notings, movement, disposal, disclosure queue; PLM — application intake, scrutiny, inspections, issuance, renewals, enforcement actions; RTM — assessments, demands, collections, arrears, refunds. **Documents:** acknowledgments, deficiency notices, inspection reports, permits/licenses/certificates (QR-verified), demand notices, receipts. **Notifications:** status updates at every state change, SLA-breach escalations, hearing/inspection schedules, payment confirmations. **KPIs:** SLA compliance %, pendency, first-time-right %, revenue collection vs demand, grievance resolution time. **Events:** request.submitted/assigned/resolved, file.moved/disposed, permit.issued/revoked, demand.raised, payment.received. **Integrations:** payment gateways/treasury, digital identity (Aadhaar/DigiLocker `[SD: F-03 §2]`), inter-department data exchange via profiles. **Compliance:** residency (F-11 — Gov tenants are primary residency consumers), records-retention acts, audit-precedence (BR-GOV-02/04). **Entitlements:** per-MS per department. **Dependencies:** CSM↔CFM (request→file), PLM↔RTM (fees), all↔trust services.

### 2.8 NGO / Temple / Trust (NGO) `[AC]`
**Branches/Locations:** chapters/centers (branch), temples/facilities, project sites. **MS modules:** DMS — donor profiles, segments, engagement history, pledges; DFM — donations, receipts, funds/grants, budgets, disbursements, utilization; TAM — sevas, hundi/collections, events/festivals, facilities, prasad dispatch; MVM — members, dues, renewals, volunteers, hours, recognition. **Documents:** donation receipts (sequential, BR-NGO-02), tax-exemption certificates, grant utilization certificates, membership cards, event reports. **Notifications:** donation acknowledgment, receipt/certificate delivery, seva confirmations, renewal reminders, utilization reports (BR-NGO-04). **KPIs:** donations by fund/segment, donor retention, fund utilization %, volunteer hours, membership growth, event participation. **Events:** donation.received, receipt.issued, fund.allocated/utilized, seva.booked/performed, member.renewed. **Integrations:** payment gateways, accounting export, communication channels. **Compliance:** charitable-institution reporting postures (jurisdiction-configurable), restricted-fund enforcement (BR-NGO-01), donor confidentiality (BR-NGO-03). **Entitlements:** per-MS (NGO without temple = DMS+DFM+MVM). **Dependencies:** DFM↔DMS (donor→donation), TAM↔DFM (seva payments), MVM↔Communication.

### 2.9 Security & Facility Management (SFM) `[AC]`
**Branches/Locations:** agency offices (branch), client sites, posts, patrol routes, facilities/assets. **MS modules:** SGM — contracts, posts, rosters, attendance (geo/QR), relief, payroll-input; PMS — routes, checkpoints, rounds, incidents, evidence (photo/notes); VMS — pre-registration, badges, blacklist, host approvals, overstay; FMM — assets, preventive schedules, tickets, SLAs, vendor work orders. **Documents:** deployment orders, attendance sheets, incident reports, visitor badges/logs, work orders, SLA reports. **Notifications:** shift reminders, absence/replacement alerts, missed-checkpoint alerts (BR-SFM-02), visitor arrival/overstay, SLA-breach escalations (BR-SFM-04). **KPIs:** post coverage %, attendance compliance, checkpoint completion %, incident rate/response time, ticket SLA compliance, visitor throughput. **Events:** shift.checkedin, checkpoint.missed, incident.reported, visitor.checkedin/out/overstay, ticket.raised/breached/closed. **Integrations:** biometric devices, CCTV/alarm systems (profiles), client-portal exports. **Compliance:** guard-licensing regulations (jurisdiction-configurable), visitor-data privacy/retention, geo-attendance evidence (BR-SFM-01). **Entitlements:** per-MS (VMS-only corporate tenant). **Dependencies:** SGM↔PMS (guard→rounds), FMM vendor work orders via Core, all↔offline Synchronization Policy (field-first suite).
