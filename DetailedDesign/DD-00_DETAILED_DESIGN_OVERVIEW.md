## 6. Shared scope model
Every protected operation is classified exactly one of:
- `PLATFORM_GLOBAL` — platform-only resource, no tenant ownership.
- `TENANT_CORE` — tenant-owned Core resource, Tenant Context required, Industry Context not applicable.
- `TENANT_INDUSTRY` — tenant + industry-owned resource, both contexts required.
- `EXPLICIT_CROSS_CONTEXT` — governed workflow with named source/target contexts and dedicated permission/policy.
- `PUBLIC` — unauthenticated public resource with no private tenant data.

A missing scope classification is a design defect.

## 7. Exact access-order invariant
`Authenticate → Tenant validation → Industry Context resolution when required → Subscription validation → License validation → Session/device/API credential validation → Entitlement snapshot → RBAC → ABAC/context → Security/compliance/residency → Resource/workflow rules → Effective Access`.

No API, worker, AI tool, webhook, offline replay, document access, or projection path may bypass this chain where applicable.

## 8. Core identifiers and type conventions
- Business identifiers: UUID v7 where newly generated by platform design; UUID v4 accepted for external/imported compatibility when required. Implementation library choice remains Development.
- Database timestamps: `timestamptz`, UTC storage.
- Human/business codes: normalized `text/varchar` with explicit unique scope.
- Money: integer minor units + ISO-4217 currency code, never floating point.
- Counters/version fields: `bigint`.
- JSON configuration/payloads: `jsonb`, schema-versioned where persisted as contracts.
- Booleans: explicit default; nullable boolean prohibited unless tri-state has defined semantics.
- Every tenant-owned row includes immutable `tenant_id`; every industry-owned row includes immutable `industry_context_id`.
- Every mutable aggregate includes `row_version bigint` for optimistic concurrency unless explicitly append-only.
